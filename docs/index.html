Colloquily Documentation

Documentation for the local Flask RAG learning assistant: application structure, runtime data, indexing, retrieval, evaluation, and operation notes.

Overview

Colloquily is a completely local, multi-subject study assistant for reviewed Markdown and PDF course material. It builds separate accepted-only indexes, generates evidence-bound questions, evaluates typed oral answers, and runs timed subject simulations with exact citations.

Local First

PDFs, indexes, request history, cache files, and the SQLite app database live under meditech_rag/data/.

Source Backed

Answers include citation IDs such as [Q1]. The UI renders them as clickable source previews with document, page, chunk type, and score.

Experiment Friendly

Prepared index profiles, evaluation scripts, metrics, and local feedback support retrieval quality comparisons.

Multi-subject quality workflow

Each subject owns a workspace under data/subjects/<slug>/ with immutable raw input, preprocessing checkpoints, review reports, generated exam packs, and a physically separate FAISS index. Only accepted knowledge units can be embedded or cited.

The admin subject workspace supports recursive Markdown/PDF discovery, hash-based incremental processing, structured local-model cleanup, suspicious-content review, question and exam-pack approval, and task-specific Ollama or LM Studio configuration.

Timed oral exams

Single-question, rapid-practice, subject-simulation, and multi-subject modes use server-side session deadlines. A multi-subject test creates one full-duration session per selected subject and a transition between them; retrieval and scoring never cross subject boundaries.

Quick Start

cd meditech_rag
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
ollama pull phi3:mini
python app.py

Open http://localhost:8000. The local development admin account is admin / admin.

Change the default admin password before using the app in any shared environment.

Architecture

The Flask app coordinates authenticated pages and calls into service modules. The RAG engine owns retrieval, prompt creation, LLM calls, request logging, and analytics refreshes.

flowchart TD Browser["Browser UI"] --> Flask["app.py Flask routes"] Flask --> DB["database.py SQLite users requests feedback quizzes"] Flask --> Engine["rag_engine.py"] Engine --> Prep["document_preprocessor.py"] Prep --> Parser["pdf_parsers: PyMuPDF or Marker"] Prep --> Source["SourceUnit pages blocks topics"] Engine --> Chunking["chunking strategies"] Chunking --> Embed["embeddings: Ollama EmbeddingGemma, SentenceTransformer, or LM Studio"] Embed --> FAISS["vector_store.py FAISS"] Engine --> Prompt["prompt_builder.py"] Prompt --> LLM["llm: Ollama or LM Studio"] Engine --> Persist["persistence.py JSON and FAISS"] Engine --> Eval["evaluator.py metrics and warnings"] Engine --> Analytics["analytics.py snapshots"]

Data And Persistence

The project keeps runtime data local. The most important location is meditech_rag/data/.

LocationContents
data/colloquily.dbDurable SQLite users, processing jobs, checkpoints, feedback, quiz sessions, and attempts.
data/pdfs/Uploaded lecture PDFs.
data/index/Legacy/runtime FAISS index, chunks, pages, documents, structure, topics, analytics, settings, request history.
data/indexes/Prepared index profiles such as baseline_page_minilm.
data/cache/SentenceTransformer cache, extracted pages cache, image and page-render caches.
data/eval/Evaluation datasets, metric registry, and generated runs.

Treat data/ as private project state. It can contain course material, user inputs, feedback, and generated model outputs.

Indexing

The app supports two index paths: the active prepared profile under data/indexes/, and the legacy/runtime index under data/index/. On startup, RAGEngine tries the active prepared profile first, then falls back to the legacy index.

Build Prepared Profiles

cd meditech_rag
python scripts/prepare_indexes.py

Evaluation

Evaluation scripts live in meditech_rag/scripts/ and store results under data/eval/runs/.

cd meditech_rag
python scripts/eval_smoke.py
python scripts/eval_chunking.py
python scripts/eval_retrieval_profiles.py
python scripts/eval_answer_subset.py
python scripts/eval_report.py

Common signals include hit_at_k, first_relevant_rank, citation_page_accuracy, duplicate_retrieval_ratio, answer text checks, and groundedness warnings.

Operational Notes

  • Use the Admin Documents page to upload PDFs and rebuild indexes.
  • Rebuild the index after changing parser, chunking, embedding, or relevant runtime settings.
  • Keep data/ private unless it has been reviewed.
  • Disable external model downloads with ST_ALLOW_DOWNLOAD = False after the desired model is cached.
  • The static documentation page uses Prism and Mermaid from CDNs when available; the written documentation remains visible without them.
